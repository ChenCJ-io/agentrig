# 03. 页面迁移批次与任务清单

## 1. 执行顺序

```text
F0 来源与基线
  → F1 UI Core / Shell
    → F2.1 Overview + Run List
      → F2.2 Plan Preview / Wizard
        → F2.3 Run Monitor
          → F2.4 Cell / Attempt Timeline
            → F2.5 Report / Failure / Recovery
              → F3 Assistant
                → F5 P0 视觉门禁

F4 Case / Assets 在 F2.2 之后可并行，但不阻塞参赛 P0。
```

## 2. F0：来源、授权与基线

### 任务

- 固定 AgentScope 来源 Commit，不从浮动工作树迁移；
- 完成开源授权确认；
- 建立 COPY/EXTRACT/REIMPLEMENT/EXCLUDE 清单；
- 截取 AgentScope 1280×1000 与 1600×1000 批准页面；
- 截取 AgentRig 当前同路由对照图；
- 建立私有关键字和素材扫描脚本；
- 为新界面添加路由级 Feature Flag。

### 交付物

```text
docs/12-AgentScope前端迁移方案/provenance.csv
web/e2e/baselines/agentscope-reference/
web/e2e/baselines/agentrig-before/
web/app/config/ui-features.ts
```

### 完成标准

- 任何一个候选文件都能追溯到来源 Commit；
- 没有授权结论时不进入公开分支；
- Flag 关闭时现有页面行为不变。

## 3. F1：UI Core 与 Shell

### F1.1 Tokens 兼容层

- 不直接覆盖 AgentRig `tokens.css`；
- 先补 AgentScope 组件需要的缺失 Token Alias；
- 选定一套统一字体、Radius、Topbar 和 Sidebar 尺寸；
- 检查 80%/100%/125% 浏览器缩放。

### F1.2 内容与状态组件

- 迁移 `MarkdownContent`；
- 新建 `LoadingState`、`EmptyState`、`ErrorState`、`PartialDataNotice`；
- 新建通用 DataTable/StickyActions/CopyableId；
- 长 Markdown、JSON、代码、表格不撑破卡片。

### F1.3 Shell

- 复用 AgentScope Shell 的尺寸、对齐、折叠和滚动方式；
- 保留 AgentRig Branding、Bearer Token 和 Target Query；
- 重写 `RuntimeTargetControl`；
- 顶栏只有一个 Target 上下文控制；
- 默认导航收敛为 Target、Assets、Runs、Assistant，高级治理放二级区。

### F1 验收

- `/targets` 和一个 Target Overview 无横向溢出；
- 导航、Target 切换、Token 对话框行为不回归；
- 中文和英文长标题均不挤掉主操作。

## 4. F2：评测主链

### F2.1 Overview 和 Run List

从 AgentScope 抽取：Summary Band、Run Summary、Filter Bar、Run Table、Error/Empty State。

AgentRig 需接入：Target Check、最近 Run、通过/失败/部分计数、工具结果来源、最近失败分类。

验收：

- 无 Run 时给出明确“新建评测”入口；
- 有 Run 时 3 秒内能看到运行状态和结果；
- API 500/401 显示权威错误，不出现演示数据。

### F2.2 Plan Preview 和 Run Wizard

页面分三步：

```text
Info: Target + 目标
Scope: Case + Profile + Repeat + Tool Result Strategy
Review: Cell/Attempt + Skip/Reject + Side Effect + Manifest Hash
```

智能助手生成的 Plan 也使用同一 `PlanPreviewVM`，但不要求与 Codex 生成相同计划。

验收：

- 用户确认前能看到 Cell/Attempt 数、真实工具调用和副作用；
- Stale Hash 禁止提交并要求重新 Preview；
- Confirm 只作用于当前 Plan Revision，连点不重复建 Run。

### F2.3 Run Monitor

抽取 Run Summary、Progress、Tabs、Cell Matrix/List 和 Sticky Actions。

验收：

- Queued/Running/Partial/Completed/Failed/Cancelled 有独立视觉语义；
- SSE 断线不清空已有 Cell；
- Cancel 不误报成完成；
- 主页只显示 Cell 摘要，长证据进入 Cell Detail。

### F2.4 Cell Detail 和 Attempt Timeline

层级：

```text
Cell Identity + Dimensions + Verdict
  → Attempts
      → Input / Assistant / Tool Call / Tool Result / Evaluation / Error
          → Raw Evidence Drawer
```

验收：

- 每个 Attempt 显示独立 Session ID 和 Repeat Index；
- Tool Result 显示 Fixture/Sample/Simulator/Real 来源；
- Failure Class 与原始错误分层展示；
- 时间统一为中国时区；
- Raw JSON 默认折叠，不破坏主叙事。

### F2.5 Report、Failure 和 Recovery

- 复用 Report Header、Tabs、Version Overview 和对比几何；
- 接入 Run Report/Quality Report；
- 展示 Failure Class、失败证据引用和 Recovery Run 链接；
- 报告中区分业务失败、评判失败、执行失败和证据不足。

验收：用户可从失败结论一步跳到对应 Cell/Attempt 证据。

## 5. F3：智能评测助手

### 页面结构

```text
Session Rail | Conversation + Plan/Run Cards | Current Context Rail
```

### 任务

- 从 AgentScope Conversation 抽 Session Rail、Message List、Composer 几何；
- 替换页内联 `ReactMarkdown` 为 `MarkdownContent`；
- 用结构化 `PlanCard`、`RunCard`、`EvidenceCard` 替代内部英文过程文本；
- 默认使用基础 Assistant Provider，AgentTeams 拓扑只在高级模式展示；
- 助手可回答 Target、Case、Run、Report 查询，也可生成 Plan；
- 确认、取消、重试必须绑定明确 Plan/Run ID。

### 验收

- “你是谁”和“你能做什么”能自然中文回答；
- 普通查询不被误判为评测计划；
- 长对话时 Composer 和当前操作仍可见；
- 不再显示 Manager 内部思考和交叉消息的英文自语。

## 6. F4：Case 与 Assets（P1）

- 迁移 Case Catalog、Detail、Editor 和 Review 外壳；
- Case 字段由 AgentRig Schema 驱动；
- 迁移 Tool Sample 的 Master/Detail 和证据预览；
- Profile 展示 Tool Mode、Provider Chain、Evaluator 和 Concurrency；
- Prompt/Knowledge/Preference 页在通用后端契约存在前不迁移。

## 7. F5：门禁和旧页下线

- 新建 AgentRig Approved Route Manifest；
- 新旧页在同一真实数据集上做行为对照；
- 评审确认后默认开启新 Flag；
- 两个发布周期无回退后删除旧路由；
- 最后拆除 `product-page.tsx` 中已迁移的页面，每次只删一个领域。

## 8. PR 切片规则

- 一个 PR 只处理一个可独立验收的路由或基础层；
- “抽取展示”和“接入真实 API”可分两个 PR，但未接 API 的页面默认不对用户开启；
- 禁止同一 PR 重写 Shell、Evaluation 和 Assistant；
- 每个 PR 都包含单元测试、E2E 或截图中至少一种可客观验收证据；
- 新 CSS 必须属于具体组件/页面，不再往单个万行 CSS 文件堆叠。

## 9. 参赛录制检查点

P0 开发中间设三个录制检查点：

1. **R1 观感检查**：Shell + Overview，确认整体视觉达到 AgentScope 水平；
2. **R2 闭环检查**：lassist Preview → Run → Cell → Failure/Recovery；
3. **R3 叙事检查**：Codex+Skill 入口和 Web Assistant 入口分别展示 AgentRig 的通用评测价值。

R2 不通过时禁止开始正式录屏。
