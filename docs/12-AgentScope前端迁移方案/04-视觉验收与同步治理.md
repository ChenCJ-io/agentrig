# 04. 视觉验收与同步治理

## 1. 验收目标

迁移完成不以“看起来差不多”为标准，而以以下四类证据为准：

1. 真实数据下的功能验收；
2. 固定 Viewport 的视觉基线；
3. 滚动、溢出、Sticky 操作和长内容的几何断言；
4. Axe 可访问性与键盘导航。

AgentScope 截图是参考基线，不要求品牌像素逐点相同；但布局层级、间距、信息密度、操作位置和状态表达需要达到同等水平。

## 2. Approved Route Manifest

AgentRig 建立自己的 `web/e2e/route-manifest.ts`：

```ts
interface ApprovedRoute {
  key: string;
  path: (data: RuntimeData) => string;
  group: "targets" | "evaluation" | "assistant" | "assets";
  dataRequirement?: "target" | "plan" | "run" | "cell" | "case";
  p0: boolean;
}
```

P0 路由：

| Key | 路由 | 数据要求 |
|---|---|---|
| `target-overview` | `/targets/:targetId/overview` | target |
| `run-list` | `/targets/:targetId/evaluation/runs` | target |
| `run-create-review` | `/targets/:targetId/evaluation/runs/new/review` | plan |
| `run-detail` | `/targets/:targetId/evaluation/runs/:runId` | run |
| `run-report` | `/targets/:targetId/evaluation/runs/:runId/report` | run |
| `cell-detail` | `/targets/:targetId/evaluation/runs/:runId/cells/:cellId` | cell |
| `assistant-empty` | `/targets/:targetId/assistant` | target |
| `assistant-plan` | `/targets/:targetId/assistant?session=:sessionId` | plan |
| `assistant-run` | `/targets/:targetId/assistant?session=:sessionId` | run |

路由清单不写死真实 ID，先通过 API 发现可用 Target/Run/Cell，找不到数据时明确 Skip 并输出原因。

## 3. Viewport 矩阵

| 类型 | 尺寸 | 用途 |
|---|---:|---|
| 批准基线 | 1600×1000 | 宽桌面完整工作台 |
| 批准基线 | 1280×1000 | 紧凑桌面与参赛录制安全区 |
| 布局冒烟 | 1440×1000 | 当前 AgentRig 对照 |
| 布局冒烟 | 1024×768 | 窄桌面，右栏折叠 |
| 可用性冒烟 | 390×844 | 只要求可访问核心内容，不要求完整桌面编辑 |

参赛录屏默认使用 1600×1000 或等比 16:10，避免 2048 宽页面缩小后文字不可读。

## 4. 数据模式

视觉验收分两套：

```text
fixture-visual/
  用脱敏、固定数据验收几何稳定性

real-backend/
  使用 AgentRig 真实 API 验收状态、数据和错误语义
```

Fixture 只能存在测试层，生产打包不允许根据 API 失败自动切到 Fixture。

Real Backend 至少覆盖：

- 无数据 Empty；
- 真实 lassist Run 的 Running 与 Terminal；
- 一个业务失败 Cell；
- 一个工具结果策略失败；
- 一个 SSE 重连/部分数据状态；
- 401、404、500 权威错误。

## 5. 几何断言

所有 P0 路由至少检查：

- `documentElement.scrollWidth <= documentElement.clientWidth`；
- Sidebar 不遮挡 Main Content；
- 顶栏不与页面标题重叠；
- 主 CTA 在首屏或 Sticky Action Bar 可见；
- 长 ID 不撑宽 Table/Message Card；
- Markdown Table/Code 在自身容器滚动；
- 左、中、右三栏分别滚动，Composer 不随消息流消失；
- 1024 宽时右栏收入 Drawer，不压缩主对话到不可用；
- 模态弹窗在键盘焦点循环内，Esc 可关闭。

## 6. 视觉对齐评分

每个页面按 100 分验收：

| 维度 | 分值 |
|---|---:|
| 信息层级与主任务可见性 | 25 |
| 布局几何、间距和对齐 | 20 |
| Loading/Empty/Error/Running/Terminal 状态 | 20 |
| 长内容、滚动和响应式 | 15 |
| 键盘、Focus 和 Axe | 10 |
| 品牌、色彩、字体和细节 | 10 |

P0 页面不低于 85 分，且前四项不得有零分缺陷。

## 7. 可访问性门禁

- 每页只有一个主 `h1`；
- Icon Button 有 `aria-label` 和 Tooltip；
- Tab 使用正确 `tablist/tab/tabpanel` 语义；
- Status 不只靠颜色表达；
- 运行进度和新消息通过受控 `aria-live` 通知，不重复朗读整页；
- Dialog 有标题、Focus Trap 和返回焦点；
- Axe critical/serious 必须为 0；
- 不使用鼠标也能完成 Preview、Confirm、Run 和打开 Cell 证据。

## 8. 失败与回退策略

| 失败 | 处理 |
|---|---|
| 视觉差异 | 保持 Flag 关闭，修复对应组件 |
| Adapter 缺字段 | 显示 Partial/Unavailable，不伪造数据 |
| 新页提交异常 | 立即关闭该路由 Flag，数据不做回滚 |
| SSE 不稳定 | 保留 Snapshot + Reconcile，暂时降级 Polling |
| 开源扫描命中 | 停止合并，删除或通用化后重新扫描 |
| 录制中出现阻断缺陷 | 回到上一个已通过 R2 的 Commit，不现场修演示数据 |

## 9. 后续同步治理

迁移完成后，通用前端能力的上游改为 AgentRig：

```text
AgentRig generic UI + ViewModels
  → AgentScope 消费
      → AgentScope 私有 Adapter / Extension / Branding
```

不再建立“每隔一段时间从 AgentScope 整页拷回 AgentRig”的同步流程。

治理规则：

- 通用视觉 Bug 和新组件先修在 AgentRig；
- AgentScope 只保留私有 Adapter、Extension、Branding 和业务页；
- 两边需要的 ViewModel 变更通过版本化 Contract 处理；
- 通用组件变更必须同时更新 AgentRig 视觉基线；
- 不允许 AgentScope 私有字段为了方便而进入通用 Props。

首批不强行建立 npm 公共包。当 AgentScope 已稳定消费至少三个 AgentRig 通用领域后，
再评估将 `view-models/` 和纯展示组件抽成版本化 workspace package。
