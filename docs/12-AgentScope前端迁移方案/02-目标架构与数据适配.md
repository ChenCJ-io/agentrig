# 02. 目标架构与数据适配

## 1. 目标目录

```text
web/app/
├── api/                         # AgentRig DTO 与 HTTP/SSE Client
├── adapters/                    # DTO → ViewModel，无 React
│   ├── evaluation-adapter.ts
│   ├── assistant-adapter.ts
│   ├── conversation-adapter.ts
│   └── assets-adapter.ts
├── view-models/                 # 通用展示契约
│   ├── evaluation.ts
│   ├── assistant.ts
│   ├── conversation.ts
│   └── assets.ts
├── components/
│   ├── ui/                  # 原子组件
│   ├── content/             # Markdown / Json / Diff
│   ├── states/              # Loading / Empty / Error / Partial
│   ├── evaluation/          # 无 Query 的展示组件
│   ├── assistant/
│   ├── conversation/
│   └── assets/
├── features/                     # Query、Mutation、SSE、表单状态
│   ├── evaluation/
│   ├── assistant/
│   ├── conversation/
│   └── assets/
├── pages/                        # 路由级组装
│   ├── targets/

│   ├── assistant/

    ├── tokens.css
    ├── global.css
    └── components.css
```

`components/` 不能直接调用 API，`view-models/` 不能 Import React，`adapters/` 不能依赖 DOM 和路由。

## 2. 通用 ViewModel

### 2.1 基础类型

```ts
type UiStatus =
  | "draft" | "pending" | "queued" | "running"
  | "passed" | "failed" | "partial"
  | "cancelled" | "interrupted" | "unknown";

interface IdentityVM {
  id: string;
  label: string;
  shortId: string;
  version?: string | null;
}

interface MetricVM {
  label: string;
  value: string | number;
  help?: string;
  tone?: "neutral" | "accent" | "success" | "warning" | "danger";
}

interface ExtensionFieldVM {
  key: string;
  label: string;
  value: string;
}
```

`extensions` 只用于附加展示，不参与核心按钮的业务判定。

### 2.2 评测类型

```ts
interface PlanPreviewVM {
  planId?: string;

interface EvaluationRunVM {
```

### 2.3 证据时间线

```ts
interface EvidenceEventVM {
  id: string;
  seq: number;
  occurredAt: string;
  kind: "input" | "assistant" | "tool_call" | "tool_result"
      | "evaluation" | "decision" | "error" | "system";
  actor: string;
  title: string;
  summary?: string;
  payload?: unknown;
  source?: "fixture" | "sample" | "simulator" | "real" | "unknown";

}
```

页面只消费已排序的 `timeline`；事件合并、时区转换和兼容旧 Event 应在 Adapter 或 Selector 完成。

## 3. Adapter 规则

AgentRig 当前 `v1.ts` 中的 `Run`、`CaseRun`、`RunReport`、`QualityReport`、`TestCase`、`Sample` 仍是 API DTO。
禁止展示组件直接使用这些类型。

Adapter 需要实现：

```text
toRunListItem(run, target)             → RunListItemVM
toEvaluationRun(run, caseRuns, report) → EvaluationRunVM
toEvaluationCell(caseRun, events)      → EvaluationCellVM
toAttempt(caseRun, attempt, events)    → EvaluationAttemptVM
toPlanPreview(preview, context)         → PlanPreviewVM
toAssistantMessage(event)              → AssistantMessageVM
toSampleAsset(sample)                  → ToolResultAssetVM
```

规则：

- 缺少字段显示“不可用”，不生成假 ID/假通过状态；
- 未知枚举映射到 `unknown`，同时保留原值用于调试；
- 时间统一进入 `date-time.ts`，默认按 `Asia/Shanghai` 展示；
- 长 ID 产生稳定 `shortId`，完整值保留复制；
- `dimensions` 必须来自真实 Snapshot/Manifest，不硬编码 App/Tool/Channel；
- Adapter 必须有纯函数单元测试。

## 4. 路由映射

保留 AgentRig Target Scoped 语义：

| AgentScope 视图 | AgentRig 目标路由 |
|---|---|
| Evaluation Overview | `/targets/:targetId/overview` |
| Batch List | `/targets/:targetId/evaluation/runs` |
| Batch Create Info | `/targets/:targetId/evaluation/runs/new/info` |
| Batch Create Scope | `/targets/:targetId/evaluation/runs/new/scope` |
| Batch Create Review | `/targets/:targetId/evaluation/runs/new/review` |
| Batch Detail | `/targets/:targetId/evaluation/runs/:runId` |
| Report | `/targets/:targetId/evaluation/runs/:runId/report` |
| Cell Detail | `/targets/:targetId/evaluation/runs/:runId/cells/:cellId` |
| Test Cases | `/targets/:targetId/evaluation/test-cases` |
| Case Review | `/targets/:targetId/evaluation/case-review` |
| Conversation | `/targets/:targetId/conversation` |
| Assistant | `/targets/:targetId/assistant` |

旧 `/targets/:targetId/evaluation/runs/:runId` 路由保留，只替换它渲染的 Page Controller。

## 5. Query 与运行状态

Query Key 必须包含资源范围：

```text
["targets", targetId]
["runs", projectId, targetId, filters]
["run", projectId, targetId, runId]
["cell", projectId, targetId, runId, cellId]
["assistant", projectId, targetId, sessionId]
```

运行期数据采用以下顺序：

```text
Initial REST Snapshot
  → SSE/Incremental Event
  → Query Cache Projection
  → Terminal REST Reconciliation
```

- SSE 中断时保留已有证据，页面显示“重连中”；
- 终态后再拉一次权威 Snapshot；
- 不允许两个独立 Poller 同时修改同一 Run Cache；
- Cancel/Confirm/Retry 按钮使用 Idempotency Key，连点不重复提交。

## 6. Shell 和上下文

AgentScope Shell 只迁移几何和交互模式，AgentRig Shell Context 保留：

```ts
interface RuntimeContextVM {
  project?: IdentityVM;
  target?: IdentityVM;
  version?: string;
  driver?: string;
  profile?: IdentityVM;
  connection: "ready" | "degraded" | "offline" | "unknown";
}
```

顶栏只展示 Target 名称、版本、Driver/Profile 和连接状态。其他详情放在 Target Overview，避免再出现长名称挤压标题。

## 7. Feature Flag 和回退

迁移期使用路由级 Flag：

```text
VITE_UI_EVALUATION_V2
VITE_UI_ASSISTANT_V2
VITE_UI_CONVERSATION_V2
VITE_UI_ASSETS_V2
```

约束：

- Flag 只决定渲染新旧 Page，不改变 API 和数据写入；
- 新旧页共用同一 Query Client，不双重提交；
- 每个 Flag 在该路由连续两个发布通过后删除；
- 旧页删除前保留最后一套 E2E 作为行为对照。

## 8. 架构验收标准

- 展示组件不 Import `~/api/*`、`useQuery`、`useNavigate` 和 Fixture；
- Page Controller 不包含大段视觉 DOM；
- Adapter 对缺字段、未知枚举和旧版 DTO 有测试；
- 所有路由带 Target/Project 范围，切换 Target 不泄漏旧 Cache；
- 新页可通过 Flag 独立回退；
- `product-page.tsx` 最终只保留过渡路由，不再承载新功能。
