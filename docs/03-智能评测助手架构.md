# 智能评测助手架构

> 状态：Current
>
> 权威边界：本文与 `src/agentrig/assistant/`、`/api/v2` 契约、`tests/v2/` 一致。

Web 评测助手让不熟悉 AgentRig 资产模型的用户用自然语言完成评测：提问、圈定范围、生成
计划、确认、提交，全程由 Core 保证事实与权限。助手可以解释与建议，但不能绕过确认或改写
运行证据。

## 1. 组件

| 组件 | 职责 | 明确不负责 |
|---|---|---|
| `AssistantService` | 会话、事件、回合的持久化与幂等接收 | 生成模型回复 |
| `BasicAssistantRuntime` | 调用 OpenAI-compatible Provider，产出回答或计划草稿 | 提交运行、跳过确认 |
| `EvaluationPlanService` | 计划状态机：draft → confirmed → submitted / cancelled | 直接执行用例 |
| `AssistantRunNotifier` | Run 终态回写会话，触发助手总结 | 修改 Run 事实 |
| AgentRig Core | 预览、确认校验、幂等提交、执行与证据 | 依赖模型文本保持正确性 |

## 2. 数据模型

- `AssistantSession`：会话与 `workspace_id`（绑定 Target 上下文，见
  [被测 Agent 上下文联动 RFC](./10-被测Agent上下文选择与联动-RFC.md)）；
- `AssistantEvent`：append-only 事件流，`seq` 单调递增，`client_message_id` 提供消息幂等；
- `AssistantTurn`：一次用户输入到助手回复的处理单元，含终态与错误投影；
- `EvaluationPlan`：目标、选择、预览快照、确认与提交幂等键；`selection_hash` 用于提交前
  漂移检测。

## 3. 关键不变量

1. **确认属于用户**：`confirm` 必须引用同会话内、草稿产生之后的新用户消息事件，且
   `confirmed_by` 与该事件作者一致。
2. **预览即冻结**：提交时重算 manifest 哈希，与确认时不一致则拒绝（`plan_stale`），不静默
   重选资产。
3. **提交幂等**：同一 `idempotency_key` 重复提交返回同一 Run；不同键触发冲突错误。
4. **completed ≠ pass**：Run 终态通知只报告状态与计数，结论以 Rule/Judge 证据为准。
5. **降级明确**：模型 Provider 不可用时，发消息返回 503 `assistant_provider_unavailable`，
   不伪造回复。

## 4. 接口

HTTP 契约位于 `/api/v2`：会话 CRUD、消息、SSE 事件流、回合取消、计划的
create/validate/confirm/cancel/submit 与 provider-health。事件流通过轮询式 SSE 提供
断线恢复（`after_seq` 续传）。

## 5. 配置

```toml
[assistant.basic_provider]
enabled = true
base_url = "https://api.example.com"
model = "your-model"
secret_ref = "env:ASSISTANT_API_KEY"
```

密钥只允许 `env:VARIABLE_NAME` 引用；未配置 Provider 时，Web 助手页面明确显示不可用，
V1 Core、MCP 与 CLI 均不受影响。
