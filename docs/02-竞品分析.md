# AgentRig 竞品分析与价值评估

> 最后更新：2026-07-07 · 状态：✅ 定稿

## 竞品全景（按定位分四象限）

| 象限 | 代表项目 | 与 AgentRig 重合度 |
|------|---------|-----------------|
| **A. LLM/Agent 评测框架（CLI/代码原生）** | [promptfoo](https://github.com/promptfoo/promptfoo)（8.3k★）、[DeepEval](https://github.com/confident-ai/deepeval)、Ragas、Giskard | **高** —— promptfoo 官方有 [Evaluate Coding Agents](https://www.promptfoo.dev/docs/guides/evaluate-coding-agents/) 指南，专门评测 Codex/Claude Agent SDK，正面撞 AgentRig 定位 |
| **B. 观测 + 评测一体化平台（服务化）** | **[Langfuse](https://github.com/langfuse/langfuse)（16k★，YC W23，MIT）**、LangSmith、Braintrust、Arize Phoenix、MLflow | **极高** —— Langfuse 几乎是「观测 + prompt 管理 + dataset + eval + 自托管」的超集，生态碾压 |
| **C. MCP / tool-using agent 专项评测** | [lastmile-ai/mcp-eval](https://github.com/lastmile-ai/mcp-eval)（基于 mcp-agent + OpenTelemetry） | **中（方向相反）** —— mcp-eval 是「用 agent 测你的 MCP server」；AgentRig 是「把测试能力通过 MCP 反向暴露给 CC」 |
| **D. Agent 快照/回归专项** | [EvalView](https://github.com/marketplace/actions/evalview-ai-agent-testing)、Gentrace | **高** —— EvalView 的「录制今天行为、静默漂移告警」「从生产 trace 自动生成回归」和 AgentRig 的「生产会话转回归用例」同形 |
| **E. 国内 AI 测试** | [Test-Agent](https://github.com/codefuse-ai/Test-Agent)、TestCopilot、MeterSphere、HttpRunner | **低** —— 偏传统测试 + AI 辅助，非 agent-native |

## 价值评估结论

**诚实判断**：作为「通用 agent 测试平台」开源，价值不高，会被 Langfuse/promptfoo 碾压。但作为有明确差异化的**细分定位项目**，有不错的 niches 价值。

**差异化分两层（产品层 > 技术层）**：

**产品层（真护城河）—— 用例积累飞轮**：CC 看代码 + 读历史数据持续生成用例，开发时跑增量、发版时跑全量，用例库越用越厚。Langfuse/promptfoo 的用例是人写的一次性资产，追不上这个飞轮（详见 `01` 产品愿景）。

**技术层（支撑飞轮，竞品部分可追）**：
1. **MCP 反向开放 + proxy**（CC 通过 MCP 驱动，AgentRig 作工具 proxy）—— 无竞品
2. **工具版本管理**（被测 agent 工具定义也版本化）—— Langfuse/promptfoo 都不做
3. **四层 mock 体系**（参数等价变形 + 样本库；L3 模拟器弃用）—— 比通用 mock 精细

> 「生产会话转回归用例」虽然做得细（三级切分），但 EvalView 已占心智，**不算首创**。

## 风险

| 风险 | 严重度 |
|------|--------|
| Langfuse 是绕不开的巨人（16k★，生态最全） | 🔴 通用定位下被碾压 |
| promptfoo 已吃下「编码 agent 评测」心智 | 🔴 |
| 命名冲突 AgentScope（阿里） | 🔴 必须改名（已选 AgentRig） |
| 垂直绑定过深（指标/mock 模拟器都和图像编辑耦合） | 🟡 脱敏工作量大 |
| 无 OpenTelemetry（竞品都走标准 trace） | 🟡 生态对接弱 |
| Qwen 强绑定 | 🟡 必须抽象成可插拔 |
| 前端原生 JS 9569 行上帝文件 | 🟡 开源接受度低 |

## 开源叙事纪律

- **不要**写成「更好的 Langfuse」或「又一个 eval 平台」
- **要**主推产品愿景飞轮：*Every change grows the suite. Every release runs it all.*（用例随开发自动积累）
- 技术层叙事（MCP 工具层测试、proxy、CC 写用例）是飞轮的支撑，不是主角
- Langfuse/promptfoo 列为**互补关系**：观测/CI 留给他们，AgentRig 主打用例积累飞轮 + 工具层测试
