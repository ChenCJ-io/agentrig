# AgentRig V2 本机演示与验收

## 1. 验收交付物

本机参考环境把四层真实连接起来：

```text
浏览器 /assistant
  → AgentRig V2（SQLite，端口 8010）
  → Matrix Bridge
  → AgentTeams v1.1.2
       ├─ Manager：规划、解释、确认后提交
       ├─ Simulation Curator：生成受控工具返回
       └─ Evidence Judge：根据冻结证据裁决
  → lassist / Pixcake 被测 Agent（端口 8000）
```

三个角色都使用 DeepSeek V4 Flash。lassist 是真实被测 Agent；AgentRig 是执行和证据
事实源；AgentTeams 是外部多 Agent 协作运行时，不进入 V1 Core，也不绕过计划确认、
角色权限或幂等约束。

验收入口只有一个：`http://127.0.0.1:8010/targets/target_lassist_local/assistant`。页面左侧管理评测会话，中间与
Manager 对话，右侧查看计划、确认边界和两个 Worker 的调用状态。

## 2. 本机文件与数据

实际密钥不进入 Git：

| 内容 | 本机位置 | 是否提交 |
|---|---|---|
| DeepSeek、Higress 与角色 Token | `.env.local-agentteams` | 否 |
| Matrix 动态身份和 access token | `.agentrig/local-demo/runtime.env` | 否 |
| AgentRig 启动配置 | `.agentrig/local-demo/agentrig.toml` | 否 |
| AgentRig SQLite | `.agentrig/local-demo.db` | 否 |
| AgentTeams 持久数据 | Docker volume `agentrig-hiclaw-data` | 否 |
| lassist 本机配置 | `../lassist-v1-develop/config/local.toml` | 否（该仓库已忽略） |

模板分别是 `deploy/agentteams/local.env.example` 和
`deploy/agentteams/agentrig.local.toml.example`。配置只保存环境变量引用；日志和页面都
不应显示模型 Key。

## 3. 一键搭建

前置条件：Docker Desktop、Python 3.12、uv、Node.js 20+、jq、screen，以及可用的 lassist
源码检出。运行前必须用绝对路径设置 `LASSIST_DIR`：

```bash
export LASSIST_DIR=/absolute/path/to/lassist
```

第一次运行：

```bash
cp deploy/agentteams/local.env.example .env.local-agentteams
# 只在这个被忽略的文件中填写本机密钥和随机管理员密码
chmod 600 .env.local-agentteams
scripts/local_demo.sh all
```

`setup`/`all` 会依次完成：

1. 安装锁定的 AgentTeams v1.1.2，并持久化 Controller、Manager 和两个 Worker；
2. 构建并应用三个 AgentRig 角色包；
3. 登录本机 Matrix，发现实际角色 ID，创建 V1 fallback 房间；
4. 创建 Manager、Curator、Judge 三条 Higress MCP route，并限制为对应 consumer；
5. 构建 Web、升级 SQLite、启动 lassist 和 AgentRig；
6. 写入本机 Target、Profile 和成功/失败两个已批准 Case，执行健康与契约检查；
7. 打开对话窗口。

日常命令：

```bash
scripts/local_demo.sh status   # 查看整体状态
scripts/local_demo.sh verify   # 重跑无副作用验收检查
scripts/local_demo.sh restart  # 重建并重启两个仓库服务，随后 seed + verify
scripts/local_demo.sh stop     # 停服务但保留数据库和 volume
scripts/local_demo.sh start    # 使用已有数据重新启动
scripts/local_demo.sh open     # 只打开对话窗口
```

Docker Desktop 首次修复网络 helper 时会弹出 macOS 管理员授权窗口。这是操作系统权限，
需要本机用户亲自确认；脚本不会读取或保存管理员密码。

## 4. 对话验收

打开页面后按以下步骤验收：

1. 左侧输入标题并点“新建”；页头应显示 `Matrix room ready`，底部 AgentTeams 状态为在线。
2. 发送：`请使用本机 lassist 目标和已批准的背景增强用例，按当前三 Agent 配置生成一次评测计划。`
3. Manager 应回复计划说明；右侧出现 draft 计划，Cases 为 1，CaseRuns 为 1，Provider
   包含 `simulation_curator`，Evaluator 包含 `evidence_judge`。
4. 点“确认计划”。页面会把自然语言确认交给 Manager；Manager 必须先记录 `confirm_plan`
   Decision，Core 绑定本次真实用户事件后才允许计划变成 confirmed。
5. 点“提交运行”。Manager 必须再记录 `submit_plan` Decision，Core 才创建一个 Run；页面右侧
   随后出现 Curator 和 Judge invocation。运行完成后点“查看
   Run”检查 lassist 对话、工具调用、受控工具结果、证据引用和最终 verdict。
6. 回到同一会话继续问：`解释这次结果，只引用本次 Run 的证据。` Manager 应能恢复会话
   上下文，并区分运行状态、Rule 结果、Judge verdict 与诊断推断。

失败也属于有效评测结果；验收重点是全链路完成、证据可追溯和裁决不伪造，而不是强行
得到 pass。

## 6. 安全与恢复边界

- 不把 `.env.local-agentteams`、`runtime.env`、数据库或 Cookie 加入 Git。
- Manager MCP 没有原始 `run_cases`；执行必须经过 EvaluationPlan 确认与提交。
- Curator 和 Judge 只能访问各自三个任务工具，不能枚举其他任务或互换角色。
- Matrix 消息带会话、turn、事件和计划 ID；Web 回复按 turn marker 关联并去除 marker；
  invocation 同时保存任务投递和 Worker 稳定回执的 Matrix event ID。
- `stop` 不删除任何数据。需要清空环境时必须单独确认目标，不能把删除动作混入启动脚本。
