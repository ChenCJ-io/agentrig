## 1. 使用方式

本文件是执行索引，不替代各专题设计。每个工作包开始前应：

1. 将对应专题从 Proposed 评审为 Accepted；
2. 确认 owner、reviewer、目标版本和 feature flag；
3. 把表中工作包拆成可独立合并的 issue/PR；
4. PR 必须链接专题编号和验收项；
5. 达到 Exit Gate 后才进入下一依赖专题。

人日是 1—2 名熟悉当前代码工程师的粗估，不包括外部 Runtime 故障、产品评审等待和真实模型预算。
应在完成首个 vertical slice 后重新估算。

## 18. 必须单独评审的决策点

以下内容不能在实现中由工程师隐式决定：

1. V2.3/V2.4/V2.5 的准确版本号与发布时间；
2. AgentTeams v1.2.2 何时成为默认开发 profile；
3. 哪些 Capability 差异默认阻断 A/B；
4. 哪些 Runtime Safety Case 为 Critical/High；
5. Production preview 是否允许保存正文及默认保留期；
6. 人工金标是否要求双审及哪些角色可以激活 Judge；
7. 哪些 Failure Pattern 可以自动进入 regressed；
8. PostgreSQL 容量达到什么阈值才引入外部队列/Trace storage；
9. Helm/OIDC/RBAC 是否由真实部署需求触发。
