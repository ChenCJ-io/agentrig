# V2.3—V2.5 验收运行手册

> 文档 ID：AR-V23-ACCEPTANCE
>
> 状态：Implemented
>
> 日期：2026-08-11

本文给出 01—09 工作包唯一的可执行验收入口，并明确区分本地确定性证据与外部 Live 证据。测试被
skip、报告存在 limitation、或命令没有在目标环境执行，都不能写成“已验证”。

## 1. 结论语义

| 状态 | 含义 | 可否宣布 Verified |
|---|---|---:|
| `Implemented / Local Verified` | 代码、迁移、契约、SQLite、Reference 和 Browser 链路通过 | 仅限本地范围 |
| `Live Pending` | live 命令和测试存在，但缺少目标 Runtime/数据库或观测文件 | 否 |
| `pass` / `complete` | 真实目标返回完整证据，报告无 failure/limitation | 是 |
| `inconclusive` / `limitation` | 没观察到必要版本、Capability、Invocation 或终态 | 否 |
| `fail` | 契约、版本、安全不变量或原子性不满足 | 否 |

统一退出码为：通过 `0`，业务/兼容失败 `2`，证据不完整 `3`，参数或环境配置错误 `64`。PostgreSQL
pytest 失败沿用 pytest 的非零退出码。

## 2. 准备本地环境

在仓库根目录执行：

```bash
uv sync --frozen --extra dev
npm ci --prefix web
npx --prefix web playwright install chromium
```

验收脚本只读取 `.venv` 和锁文件，不自动修改依赖。Chromium 未安装时 Browser 步骤会明确失败。

## 3. 本地确定性验收

```bash
scripts/accept_v23.sh local
```

该命令按失败即停的顺序执行：

1. 11 个 Skill 的 contract、SKILL.md 内容 hash、角色工具边界、JSON Schema 和 package 引用；
2. 全量 Python pytest、Ruff 和 mypy；
3. 隔离临时 SQLite 的全量 upgrade、downgrade 一版、再次 upgrade 和 current；
4. Web unit、typecheck、production build 和 accessibility/browser contract；
5. 自动选择空闲端口，启动临时 FastAPI、SQLite 与 Public Reference Target；
6. 无 `page.route` 核心 API Mock 地由浏览器创建真实 A/B Run，并读取服务端 Capability、
   QualityReport、ComparisonReport 与 ReleaseGate；
7. 无论 Browser 成败都只停止本次临时状态目录记录的两个受控进程。

本地模式不需要 AgentScope、AgentTeams 或 PostgreSQL，也不会把相关 skip 当作 Live 通过。

2026-08-11 在 Python 3.12 开发环境和 Python 3.13 隔离环境的实测结果均为
`189 passed, 9 skipped`；Web `35 passed` 且已收集 helper/presenter 范围 100% coverage，Browser contract
`2 passed`，真实后端 Browser `1 passed`。
9 个 skip 分别需要
AgentScope AG-UI、legacy Pixcake、Goose ACP 或 PostgreSQL 外部环境，因此只能证明本地范围。
同日另在回环端口的一次性 PostgreSQL 17.7 cluster 执行 `tests/v1/test_postgresql.py`，
`4 passed`，覆盖双 Worker claim、lease/fencing、并发终态单次通知与 OTLP retention，并完成
0001→0005、0005 downgrade 和再次 upgrade。隔离 Python 3.12 安装新构建 wheel 后，内置 Web、
Safety manifest 与 0005 migration smoke 也通过。该结果证明集成契约，不代替目标
部署的容量/SLO benchmark。

## 4. 外部 Live 验收

### 4.1 必需环境变量

```bash
export AGENTRIG_TEST_POSTGRES_URL='postgresql+asyncpg://USER:PASSWORD@HOST:5432/agentrig_test'
export AGENTRIG_TEST_AGENTSCOPE_AGUI_URL='https://agentscope.example.internal'
export AGENTRIG_TEST_AGENTSCOPE_SECRET_REF='env:AGENTRIG_TEST_AGENTSCOPE_TOKEN'
export AGENTRIG_TEST_AGENTSCOPE_TOKEN='runtime-issued-short-lived-token'
export AGENTRIG_AGENTTEAMS_V112_OBSERVATION='/secure/path/agentteams-v1.1.2-observation.json'
export AGENTRIG_AGENTTEAMS_V122_OBSERVATION='/secure/path/agentteams-v1.2.2-observation.json'
```

PostgreSQL 数据库名必须包含 `test`，集成测试否则主动 skip，避免误清理普通数据库。AgentScope Secret
必须通过 `env:` 引用；报告只记录 endpoint hash、版本、事件键与序号，不记录 token、prompt、reasoning
或 Tool body。

可选覆盖：

```bash
export AGENTRIG_TEST_AGENTSCOPE_VERSION='2.0.6'
export AGENTRIG_TEST_AGENTSCOPE_RUN_PATH='/agui'
export AGENTRIG_TEST_AGENTSCOPE_HEALTH_PATH='/health'
export AGENTRIG_TEST_AGENTSCOPE_CAPABILITY_PATH='/capabilities'
export AGENTRIG_V23_ACCEPTANCE_OUTPUT_DIR='.agentrig/v23-live'
```

### 4.3 执行

```bash
scripts/accept_v23.sh live
```

完整本地加 Live：

```bash
scripts/accept_v23.sh all
```

Live 模式依次执行 PostgreSQL 多 Worker/retention 测试、AgentScope 版本化兼容探针，以及两个相互隔离
的 AgentTeams compat report。默认输出：

```text
.agentrig/v23-live/
  agentscope-v2.0.6.json
  agentteams-v1.1.2.json
  agentteams-v1.2.2.json
```

报告应被上传到受访问控制、不可覆盖的 ReleaseEvidence 存储；提交到仓库前先确认其中只有脱敏元数据。

## 6. CI 映射

| CI Job | 覆盖范围 |
|---|---|
| `backend` | Python 3.12/3.13 全量测试 |
| `quality` | Ruff、mypy、依赖审计 |
| `frontend` | typecheck、coverage、Browser/accessibility、build |
| `postgresql` | migration 往返、SKIP LOCKED、lease fencing、OTLP retention |
| `reference-demo` | 真实 Reference A/B、Gate summary、ReleaseEvidence 完整性 |
| `real-backend-browser` | Browser→FastAPI→SQLite→Reference Target，无核心 API Mock |
| `package` | wheel/sdist、内置 Web、安全套件 manifest 和安装后 smoke |

AgentScope/AgentTeams 需要组织内受控环境和 Secret，因此应作为 nightly/Release workflow 调用同一
`live` 入口；普通 PR 的 fixture report 只能证明契约，不证明外部 Runtime 可用。

## 7. 归档清单

发布负责人应同时归档：git SHA、锁文件 hash、migration current、Skill contract manifest hash、
Quality/Comparison/Gate、SafetyReport/Gate、AgentScope live report、AgentTeams 两份 compat report、
PostgreSQL job 日志与测试摘要。任何一项为 skip、limitation 或 inconclusive 时，都要在 Release 记录中
保留原因和 owner，不能删除该状态后只保留成功报告。
