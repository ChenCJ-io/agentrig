## 1. 目标

本专题不重新设计 V2.2，而是把已经接受的方向细化为可以逐项实现和验收的工作包：

1. 从终态 Run 派生稳定 `QualityReport`；
2. 从现有 A/B pair 派生 `ComparisonReport`；
3. 由版本化 `ReleasePolicy` 纯函数生成 `ReleaseGateResult`；
4. 将 Gate 接入 CLI、GitHub Check 和 Web；
5. 补齐 real-backend E2E、Skill contract、确定性故障矩阵和 OTLP export；
6. 规范 usage/cost，避免缺失值、价格变化和缓存 token 造成错误结论。

## 2. 非目标与不变量

- 不新增第二套 Run、CaseRun 或“质量运行”表。
- 不修改已经发布的 `agentrig.run-report.v1` 和 `agentrig.release-evidence.v1` 字段语义。
- 不将 Collector、GitHub 或前端计算结果作为业务事实。
- 不把基础设施错误自动归类为 candidate regression。
- 不让 warning 默认阻断发布；是否阻断由调用方明确配置。
- 不用小样本性能分位数做 blocking check。

## 3. 领域契约

### 3.1 UsageSnapshot

当前 DriverEvent 的 `usage` 是开放字典。首版不强制所有 Driver 同时支持全部字段，但归一层必须输出：

```json
{
  "schema_version": "agentrig.usage.v1",
  "model": "provider/model-id",
  "input_tokens": 120,
  "output_tokens": 48,
  "total_tokens": 168,
  "cached_input_tokens": 80,
  "reasoning_tokens": null,
  "raw_usage_present": true,
  "cost": {
    "amount": "0.00124",
    "currency": "USD",
    "kind": "estimated",
    "pricing_source": "repository-snapshot",
    "pricing_effective_at": "2026-08-10T00:00:00Z",
    "pricing_snapshot_hash": "sha256:..."
  },
  "missing_fields": ["reasoning_tokens"]
}
```

规则：

- 数量未知时为 `null`，不得填零；
- `total_tokens` 只有在来源提供或各分项可完整相加时才生成；
- 缓存 token 不得同时计入普通 input cost；
- 价格使用运行时冻结快照，历史成本不得按今天价格重算；
- 无可靠模型标识或价格时只报告 token，`cost=null`；
- 原始 provider usage 可脱敏保存为 evidence，但报告只读取归一字段。

### 3.2 QualityReport

`agentrig.quality-report.v1` 的稳定结构：

```text
identity
  schema_version, run_id, source_snapshot_hash, generated_at
scope
  case/target/version/repeat/comparison dimensions
outcomes
  pass, fail, inconclusive, evaluation_error, skipped, execution_error
latency
  run, case_run, driver, ttft, curator, judge
usage
  token totals, cached tokens, cost, missing_fields
reliability
  retries, timeouts, error codes, recovery outcomes
collaboration
  decisions, provenance, invocations by role and status
evidence_quality
  valid/missing/foreign refs, redaction status
limitations[]
```

生成约束：

1. 只接受终态 Run；
2. 使用稳定分页读取全部 CaseRun/Event/Evaluation/Invocation；
3. 百分比同时保存 numerator 和 denominator；
4. p95 样本少于策略要求时标记 `observation_only=true`；
5. 生成期间来源发生变化则失败重试，不输出混合快照；
6. canonical hash 不包含生成时间、展示文案或数据库返回顺序。

首版 p50/p95 使用 nearest-rank；A/B 聚合耗时和 Token 变化使用“candidate 总量相对 baseline 总量”的
比例，不平均每个 pair 的百分比，避免小基数 pair 获得过高权重。

### 3.3 ComparisonReport

`agentrig.comparison-report.v1` 复用 `comparison_pair_id` 和 `comparison_role`。分类固定为：

- `unchanged_pass`
- `unchanged_fail`
- `regression`
- `fix`
- `changed_inconclusive`
- `infrastructure_error`
- `incomplete_pair`

每个 pair 保存 baseline/candidate 的 CaseRun、主 Evaluation、Capability Snapshot hash、关键 evidence refs
和 metric delta。若两边 Capability 的阻断级字段不同，则 pair 为 `incomparable_environment`，不得继续
计算产品 regression；具体规则见 04 号专题。

### 3.4 ReleasePolicy

首版继续使用仓库内版本化 JSON：

```json
{
  "schema_version": "agentrig.release-policy.v1",
  "name": "default-agent-release",
  "policy_version": "1.0.0",
  "blocking": {
    "max_outcome_regressions": 0,
    "max_infrastructure_errors": 0,
    "max_incomplete_pairs": 0,
    "max_incomparable_environment_pairs": 0,
    "min_evidence_reference_validity": 1.0
  },
  "warnings": {
    "max_duration_regression_ratio": 0.15,
    "max_token_regression_ratio": 0.10
  },
  "minimum_samples": {
    "comparable_pairs": 1,
    "latency": 20,
    "token": 1
  }
}
```

策略通过 Pydantic 严格校验；字段有单位、上下界和默认值。Gate 保存 canonical policy hash，发布
证据同时绑定仓库 Git SHA，因而可以定位并重放该 revision 中的策略文件；首版不在 Gate 结果里复制
完整策略正文。

### 3.5 ReleaseGateResult

Gate 是以下纯函数：

```text
gate(QualityReport, ComparisonReport, ReleasePolicy)
  → pass | warn | fail | inconclusive
```

优先级：`fail > inconclusive > warn > pass`。每个 check 输出名称、severity、actual、threshold、outcome
和 evidence refs。关键输入缺失或可比较样本不足时必须是 `inconclusive`；来源 hash 不一致时拒绝生成
混合结果，调用方重试。阻断策略明确禁止的 infrastructure/incomplete/incomparable pair 仍为 `fail`。

## 4. 服务、API、CLI 与 UI

### 4.1 后端模块实现

```text
src/agentrig/reporting/
  quality.py
  comparison.py
  canonical.py
  schemas.py
src/agentrig/gates/
  policy.py
  evaluator.py
  schemas.py
```

聚合逻辑保持纯函数，Repository 读取和 HTTP 序列化放在外围。避免继续扩大单个 ReportingService。

### 4.2 HTTP API

```text
GET /api/runs/{run_id}/quality-report
GET /api/runs/{run_id}/quality-report?format=markdown
GET /api/runs/{run_id}/comparison-report
GET /api/release-policies/default
POST /api/runs/{run_id}/release-gate:evaluate
```

Gate 请求体固定为 `{"policy": <agentrig.release-policy.v1>}`，并支持 `?format=markdown`。首版按请求
派生，不提供 `GET release-gate`，也不持久化业务表；CLI/CI 保存的 JSON 是不可变交付产物。组织级
策略、审批和查询历史另立持久化 RFC。

### 4.3 CLI

```bash
agentrig report quality --run-id run_xxx --output quality.json
agentrig report comparison --run-id run_xxx --output comparison.json
agentrig gate evaluate --run-id run_xxx --policy policy.json --output gate.json
```

退出码：`pass=0`、`warn=0`、`fail=2`、`inconclusive=3`、使用错误 `=64`。提供 `--fail-on-warn` 时 warn
返回 2，但产物中的 verdict 仍保持 warn。

默认策略位于 `configs/release-policies/default-agent-release.json`。

### 4.4 GitHub Check

- PR workflow 运行固定 reference A/B suite；
- 上传 Quality/Comparison/Gate JSON 和 Markdown；
- Check summary 展示 verdict、regression、环境不可比和证据链接；
- 注释必须避免包含 prompt/tool result 正文；
- 外部 live compatibility 结果默认 report-only，不让模型波动阻断普通 PR。

### 4.5 Web

Run 详情增加“质量”和“版本对比”页签。前端只展示服务端结果，不重算分类或门禁。小样本、缺失字段、
环境不可比和 infrastructure error 必须有不同视觉语义。

### 4.6 兼容行为

新 CaseRun 在首条 prompt 前冻结 Capability Snapshot；A/B 阻断级差异产生
`incomparable_environment`。历史 CaseRun 没有快照时仍返回 `legacy_unavailable`/unknown，并使要求
Capability Gate 的结论 inconclusive，不根据当前 Target 状态猜测回填。

## 5. Skill Contract 与真实 E2E

### 5.1 Skill Manifest

统一 manifest 至少包含：

```text
id, name, role, path, contract_version, content_hash,
allowed_tools, input_schema, output_schema, fixtures,
compatible_agentrig, compatible_agentteams
```

构建时检查角色工具隔离、Schema、示例、相对引用、package 内容和兼容版本。AgentTeams v1.2.2 的
远端分发状态由 02/04 专题补充，不能只验证本地 zip。

### 5.2 real-backend Playwright

每 PR 至少一条浏览器链路必须真实经过：

```text
Browser → FastAPI → temporary DB → Reference Target → Run/Event/Evaluation → Report
```

Mock API 测试继续保留并明确命名为 UI contract/accessibility tests。

## 6. 故障矩阵

必须覆盖：

- pair 缺半边、重复 pair 和版本不匹配；
- Evaluation 缺失、foreign evidence refs；
- usage 缺失、负数、分项不一致、未知价格；
- 生成期间来源变化；
- Matrix/Driver 重复、乱序、超时；
- OTLP exporter 不可达；
- Gate policy 越界、未知字段和 hash 不一致；
- Markdown/JSON 下载文件名与内容注入。

## 7. 实施顺序

1. 先实现 canonical snapshot 与 UsageSnapshot。
2. 实现 QualityReport 纯函数、Schema 和 API。
3. 实现 ComparisonReport 与 Capability 可比性挂钩。
4. 实现 Policy/Gate、CLI 和产物。
5. 接入 GitHub Check 与 Web。
6. 补 Skill contract、real-backend E2E、故障矩阵和 OTLP export。
7. 运行一个完整 release dry-run，再将默认策略从 report-only 升级为 blocking。

## 8. 验收标准

- [x] 相同来源快照连续生成 20 次，JSON 的业务字段和 hash 完全一致；
- [x] 每种 pair 分类、缺失状态和错误归因都有测试；
- [x] Usage 缺失不显示为 0，历史成本绑定价格快照；
- [x] CLI 对 `fail` 和 `inconclusive` 分别返回 2 和 3；Reference CI 以已知回归验证 `fail` 负向控制；
- [x] GitHub/Web/CLI 展示同一 Gate JSON，不存在三套计算；
- [x] real-backend Playwright 不 Mock 核心 API；
- [x] 全部现有 Skill 通过 manifest、role、tool、schema 和 package 检查；
- [x] Collector 失败不改变 Run 终态；
- [x] 旧 RunReport、ReleaseEvidence 和客户端仍可使用。

## 9. 回滚

所有能力以新增 API/CLI 和 feature flag 上线。关闭 Gate workflow 或 observability 不影响 Run。报告为
派生对象，可回滚代码重新生成；已发布的报告产物不可覆盖，只能以新版本重新发布。
