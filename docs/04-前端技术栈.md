# AgentRig 前端技术栈

> 最后更新：2026-07-07 · 状态：✅ 决策已定（用户确认）

## 决策

**全部重写**现有原生 JS 前端（`app.js` 9569 行上帝文件），改用以下栈：

| 层 | 选型 | 理由 |
|----|------|------|
| 框架 | **React 19 + TypeScript** | 开源生态最大、贡献门槛最低、CC/Codex 训练数据占优 |
| 构建 | **Vite 6**（纯 SPA） | 不需要 SSR，Next.js 的 RSC/App Router 对管理台是过度复杂 |
| UI | **shadcn/ui + Tailwind v4 + Radix** | 2024-2026 开源绝对标配，代码进仓库可定制 |
| 服务端状态 | **TanStack Query v5** | REST + SSE 事实标准 |
| 客户端状态 | **Zustand** | 比 Redux 轻量现代 |
| 路由 | **TanStack Router** | 类型安全 |
| 表格 | **TanStack Table v8** | 用例管理大头 |
| 代码编辑器 | **CodeMirror 6** | prompt/tool 编辑，比 Monaco 轻 |
| 图表 | **Tremor** 或 **shadcn/chart** | dashboard 风格统一 |
| 测试 | **Vitest + Playwright** | Vite 原生单测 + E2E |

## 三个关键选择

1. **React 而非 Vue/Svelte** —— 面向全球开源 + 适配 CC/Codex，React 双优胜出。Vue/Nuxt 仅在「团队完全不会 React + 只面向国内」时考虑。
2. **Vite SPA 而非 Next.js** —— 后端是独立 FastAPI，前端纯消费 REST + SSE，Next.js 的 SSR/SEO/RSC 全用不上。例外：未来开源着陆页/文档站可单独用 Astro/Next.js 做门面。
3. **shadcn/ui 而非 Ant Design / MUI** —— Ant 国际开源感弱、MUI 重且定制难。shadcn「代码 copy 进仓库」模式定制度最高，配 AgentRig 独立视觉身份。

## 重写策略：全部重写，不渐进迁移

- 现有 `app.js` 9569 行 + 原生 JS 无构建 = 最大开源负债，贡献门槛极高
- 重写**根治旧债**：三层 token 覆盖、设计系统没落地、字体断裂（旧 MEMORY 已记）—— 新栈从设计系统起步一次解决
- 工作量 **2-3 周**（一个熟练前端 + CC/Codex 辅助）

### 重写顺序

1. **设计系统**（shadcn token 化，先解决「UI 不优美」根因 —— 用户既有偏好：无页头横栏、内容直接进卡片）
2. **用例管理**（最大模块，对应 `tc_workspace.js`）
3. **批量回归 + 报告**（`batch_workspace.js` + `batch_report.js`）
4. **指标观测**（`metrics_workspace.js` + `weekly_report_workspace.js`）
5. **工具/提示词编辑器**（`tool_version.js` + `prompt_version.js` + `prompt_editor.js`）

## dogfooding 叙事（注意边界）

✅ 正确：**用 CC/Codex 开发 AgentRig 平台本身；AgentRig 帮各垂直业务 agent 做回归。**
❌ 错误：「用 AgentRig 测 CC」—— CC 是驱动者不是被测对象（详见 `01-定位与命名.md` 三层角色）。

可强化的真实 dogfooding：AgentRig 平台自身也维护一份回归用例，开发者用 CC 改 AgentRig 代码时，CC 通过 AgentRig 自己的 MCP 跑这些用例 ——「自己用自己」，但被测是 AgentRig 的后端逻辑，不是 CC。
