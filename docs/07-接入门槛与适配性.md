# AgentRig 接入门槛与适配性

> 最后更新：2026-07-07 · 状态：✅ 校准(主路径 = CC 写用例)
> 数据来源：`models.py` / `mock_script_builder.py` / `case_runner.py` / `mcp_tools/authoring` 实勘

## 核心判断(校准)

⚠️ **用对尺子**：AgentRig 的主用户是**编码 Agent(CC/Codex)**，不是人。门槛衡量标准不是「人手写多简单」，而是：

1. **CC 调用 MCP 工具顺不顺**(authoring 工具 schema 清晰度 + 辅助工具齐全度)
2. **CC 写的 mock 可信不可信**(不凭空臆造、贴合真实工具行为)

promptfoo/Langfuse 的易用是对人；AgentRig 的易用是对 Agent。**不要用错尺子自挫**——mock JSON 4078 行对人劝退，对 CC 不是问题。

## 一、现状实勘(数据有效，解读校准)

| 维度 | 现状 | 对人 | 对 CC(主路径) |
|------|------|------|------|
| 测试 schema | `initial_state` 枚举 `project_with_images` 等；`applies_to_channels` 默认 Pixcake | 看不懂 | CC 能读懂，但**语义对非 Lassist agent 不成立**(降 v0.2) |
| mock 剧本 | JSON，98-4078 行 | 劝退 | **CC 不在乎行数**，但凭空写的 mock 可能不真实 |
| authoring MCP 工具 | `upsert_test_case` 嵌套 dict | 人工不可用 | **CC 主路径，OK** |
| 录制能力 | `mock_script_builder` 直连 Lassist RDS | — | **核心价值**：给 CC 真实样本，让 mock 可信 |
| 零 mock 起步 | L3 兜底婚纱照假数据 | — | 无意义；**proxy 透传是新能力** |

**关键认知**：当前架构是「模拟工具结果」不是「代理真实工具」。proxy 透传 + 录制是 v0.1 新能力(见 `06`)。

## 二、对标竞品：尺子不同，不是同类

| | 主用户 | 第一次测试谁写 |
|---|---|---|
| promptfoo | 人 | 人写 YAML |
| Langfuse | 人 | 人配 SDK |
| **AgentRig** | **编码 Agent** | **CC 看代码 + 读数据生成** |

不是同类产品对比 —— AgentRig 是 agent-native testing(AI 测 AI)，高一档。

## 三、用例来源：CC 看代码 + 读历史数据(主路径)

**主流程**(不是「录制代替人写」，是「CC 写 + 录制提供可信数据」)：

1. CC 看业务 agent 代码(理解行为 + 工具)
2. CC 调 AgentRig MCP 工具读历史数据 / 真实样本(`get_tool_result_samples`、录制回放)
3. CC 基于代码理解 + 真实样本，生成贴合可信的 mock + 用例
4. CC 跑用例，看回归
5. 用例沉淀，发版时跑全量(飞轮)

**录制/真实样本的真正价值 = 给 CC 提供可信数据**，避免它凭空臆造 mock(臆造的 mock 测的是「CC 想象的 agent」不是真实 agent)。这是 Phase 1.7(录制泛化)的定位。

## 五、录制泛化的改造面

`mock_script_builder.build_mock_script_from_runs(runs)` 核心是纯函数(turn/tool_call 展平)，**可复用**。改造点：

1. **数据源**：直连 Lassist RDS → AgentRig proxy trace(或任意 OTLP)
2. **删 Lassist 语义**：`_infer_initial_state`、`_synthesize_apply_creative`、`<context>` XML 解析
3. **`initial_state` agent-agnostic**：纯 `attachments` + 自由 KV(v0.2 做深度，v0.1 先能录非 Lassist agent 即可)

工作量约 **3-4 天**(Phase 1.6 之后)。
