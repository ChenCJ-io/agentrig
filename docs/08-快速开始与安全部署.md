# AgentRig 快速开始与安全部署

本文面向第一次运行 AgentRig 的开发者和准备受控部署的运维人员。若只想验证项目能力，优先
使用公开确定性 Demo；若要复核三 Agent/Matrix 协作，再进入完整本机环境。

## 1. 选择运行路径

| 路径 | 适用场景 | 外部依赖 |
|---|---|---|
| **Public Reference Demo** | 首次体验、CI、协议和证据复核 | Python 3.12+、uv、Node.js 20+ |
| **最小本地服务** | 接口开发、MCP 接入、Web 调试 | Python 3.12+、uv、Node.js 20+ |
| **完整 AgentTeams Demo** | 三角色协作、Matrix 与真实被测 Agent 验收 | Docker、lassist、部署侧模型与服务凭据 |

## 2. Public Reference Demo

该路径运行成功、策略回归和显式恢复三个固定场景。首次安装依赖需要访问软件源；场景执行本身
不调用模型、不访问外部服务，也不依赖私有项目。

```bash
git clone https://github.com/ChenCJ-io/agentrig.git
cd agentrig
scripts/reference_demo.sh all --profile reference-ci
```

默认入口：

| 服务 | 地址 |
|---|---|
| AgentRig Web/API | `http://127.0.0.1:8020` |
| Reference Target | `http://127.0.0.1:8091` |

运行证据保存在 `.agentrig/reference-demo/evidence/`。严格校验会核对 Git SHA、版本、SBOM、公开
配置、所有产物 Hash 和 Run/CaseRun 交叉引用。策略回归场景还会导出同一来源快照的
`quality-report.json`、`comparison-report.json` 和预期为 `fail` 的 `release-gate.json`：

```bash
scripts/reference_demo.sh validate-evidence --require-clean-source
scripts/reference_demo.sh status
scripts/reference_demo.sh down
```

完整场景契约与拆分命令见 [Public Reference Target](../examples/reference_target/README.md)。

### 3.1 生成质量报告和执行发布门禁

QualityReport 只接受终态 Run；ComparisonReport 和 Release Gate 还要求该 Run 包含 baseline/candidate
A/B 配对。HTTP API：

```text
GET  /api/runs/{run_id}/quality-report
GET  /api/runs/{run_id}/comparison-report
POST /api/runs/{run_id}/release-gate:evaluate
```

本地 CLI 使用当前 `agentrig.toml` 的数据库。先执行 migration，再运行：

```bash
uv run agentrig report quality --run-id run_xxx --output quality.json
uv run agentrig report comparison --run-id run_xxx --output comparison.json
uv run agentrig gate evaluate \
  --run-id run_xxx \
  --policy configs/release-policies/default-agent-release.json \
  --output release-gate.json
```

Gate 退出码为 `pass/warn=0`、`fail=2`、`inconclusive=3`；增加 `--fail-on-warn` 后 warn 也返回 2，
但 JSON 中的 verdict 仍为 warn。成本只在 ExecutionProfile 携带冻结的
`agentrig.pricing-snapshot.v1`、事件模型精确匹配且 token/cache 分项足够时计算；否则保持
`null` 并输出 limitation，不会用当前价格回填历史 Run，也不会填零。

Profile 中的价格快照示例：

```json
{
  "pricing_snapshot": {
    "schema_version": "agentrig.pricing-snapshot.v1",
    "source": "release-2026-08-11",
    "effective_at": "2026-08-11T00:00:00Z",
    "currency": "USD",
    "rates": [
      {
        "model": "example-model-v1",
        "input_per_million": "1.00",
        "output_per_million": "2.00",
        "cached_input_per_million": "0.10"
      }
    ]
  }
}
```

## 4. 最小配置

`agentrig.toml`：

```toml
[server]
host = "127.0.0.1"
port = 8000

[database]
url = "sqlite+aiosqlite:///./.agentrig/agentrig.db"

[proxy]
public_url = "http://127.0.0.1:8000/proxy"
backends = { business = "http://127.0.0.1:9001/mcp/" }

[execution]
default_concurrency = 4
max_concurrency = 20
max_repeat_count = 20
max_cases_per_run = 200
max_planned_case_runs = 1000
real_tool_allowlist = []
python_driver_allowlist = []
subprocess_allowlist = []
durable_scheduler_enabled = false
job_lease_seconds = 60
job_max_attempts = 3
worker_poll_seconds = 1.0
worker_registration_ttl_seconds = 30

[target_network]
allow_private_networks = false
allowed_hosts = ["localhost", "127.0.0.1", "::1"]

[reporting]
max_report_case_runs = 10000
max_export_records = 10000

[run_otlp_export]
enabled = false
endpoint = ""
service_name = "agentrig"
timeout_seconds = 5.0
header_secret_refs = {}

[production_evidence]
enabled = false
max_request_bytes = 4000000
max_spans_per_request = 2000
max_attribute_count = 128
max_attribute_value_chars = 4096
default_retention_days = 30
max_retention_delete_traces = 10000
```

`run_otlp_export` 是终态 Run 的 best-effort 元数据导出，只包含 ID、计数、状态和时间，失败不改写
Run 结果。开启时 `endpoint` 必须是绝对 HTTP(S) URL，请求 Header 只能用
`header_secret_refs = { Authorization = "env:OTLP_AUTHORIZATION" }` 引用环境变量。

`production_evidence` 默认关闭；开启后仍需要先创建 Project 和 Ingest Source，OTLP/HTTP
`POST /v1/traces` 必须同时携带 `X-AgentRig-Project`、`X-AgentRig-Source` 和该 Source 一次性
返回的 Bearer Token。全局服务 Token 不能代替 ingest 凭据。

持久化数据库必须先执行 Alembic migration。服务启动时会拒绝未初始化或 revision 落后的数据库，
不会用 ORM 元数据静默补表。

PostgreSQL 使用环境变量覆盖：

```bash
export AGENTRIG_DATABASE__URL='postgresql+asyncpg://user:pass@localhost/agentrig'
uv run agentrig db upgrade
```

## 5. 鉴权与 Secret

共享或公网环境必须启用 Bearer Token。配置文件只保存环境变量引用，不保存实际值：

```toml
[server]
api_token_ref = "env:AGENTRIG_ACCESS_TOKEN"
```

```bash
export AGENTRIG_ACCESS_TOKEN='replace-with-a-random-token'
```

Codex MCP 配置同样只引用环境变量：

```toml
[mcp_servers.agentrig]
url = "http://127.0.0.1:8000/mcp/"
bearer_token_env_var = "AGENTRIG_ACCESS_TOKEN"
```

Target 和模型凭据只接受 `env:VARIABLE_NAME` 引用。不要把实际 Token 写入 `agentrig.toml`、
Target、Skill、Agent 配置或日志。

## 6. 出站与工具安全边界

- Target HTTP(S) 地址在保存和每次运行前都经过 URL、DNS、私网与主机 allowlist 校验。
- 本地开发只放行 `localhost`、`127.0.0.1` 和 `::1`；共享环境应替换为精确受信主机。
- 不要为了图方便在生产环境设置 `allow_private_networks = true`。
- Real Tool 只有部署 allowlist、ExecutionProfile Provider 链和用户授权同时成立时才能调用。
- Python/subprocess Driver 必须由部署管理员预先加入 allowlist；MCP 不能上传或执行动态代码。
- 报告和证据导出超过上限时明确失败，不会静默截断。

可信反向代理若会剥离并重写身份 Header，可显式配置：

```toml
[server]
trusted_principal_header = "x-authenticated-user"
```

不要直接信任来自公网客户端的身份 Header。

## 7. 容器访问宿主机 Proxy

容器内 Agent 不能通过回环地址访问宿主机。此时应同时启用服务 Token，并配置容器可达地址：

```toml
[server]
host = "0.0.0.0"
port = 8000
api_token_ref = "env:AGENTRIG_ACCESS_TOKEN"

[proxy]
public_url = "http://host.docker.internal:8000/proxy"
```

AgentRig 会把服务 Token 与 CaseRun 的短期 Scope 一起注入 ACP MCP 配置；短期 Scope 不能替代
服务端的 Target、Provider 和工具 allowlist。

## 9. Project 边界与耐久执行

共享部署应使用全局服务 Token 创建 Project，再为客户端签发最小权限的 Project API Key。
Project Key 仅在 `/api/projects/{project_id}/...` 下生效，可用 scope 为 `read`、`run`、
`review`、`ingest`和 `admin`；Token 只在签发响应中出现一次，数据库只保存 hash。

开启耐久调度后：

```toml
[execution]
durable_scheduler_enabled = true
job_lease_seconds = 60
job_max_attempts = 3
```

```bash
uv run agentrig worker --worker-id worker-a
```

SQLite 只允许一个活跃 durable worker；多 Worker 必须使用 PostgreSQL 的
`FOR UPDATE SKIP LOCKED` 路径。每次外部 Real Tool 请求前会先持久化 no-retry fence；如果 Worker 在请求
后、记录结果前崩溃，Job 进入 `dead` 而不会自动重放外部副作用。

## 11. 常见问题

| 现象 | 处理 |
|---|---|
| 启动提示数据库未初始化 | 执行 `uv run agentrig db upgrade` |
| Web 返回 401 | 从右上角设置访问令牌，确认服务端和浏览器使用同一 Token |
| 本地 Target 被出站策略拒绝 | 将精确主机加入 `target_network.allowed_hosts`，不要全局放开私网 |
| 容器无法访问 Proxy | 使用容器可达地址，并同时启用 Bearer Token |
| Reference 严格校验拒绝脏工作区 | 正式证据应从干净 checkout 生成；开发中可先运行普通校验 |
| AgentTeams 状态不可用 | 运行 `scripts/local_demo.sh status` 和 `verify`，不要伪装为 Core 成功 |
| 第二个 SQLite worker 被拒绝 | 这是预期安全边界；多 Worker 切换到 PostgreSQL |
| QualityReport 成本为 `null` | 检查 Profile 价格快照、事件 model 与 token/cache 分项，不要在报告时回填当前价格 |

接口和模块细节见 [V1 实现与接入](./01-核心Agent价值复核与讨论交接.md)，安全漏洞报告方式见
[SECURITY.md](../SECURITY.md)。
